You can use the catalogue without the skill. This page shows how, using the same steps the process follows. It is slower and less thorough than the process, because code does two of the steps (ruling out techniques and ordering them) and checks every technique against your material, which is tedious by hand. For a first look at what might fit, or to check what the skill chose, it works well.

## 1. Write down the request and the three settings

Write your request in one sentence and note its parts. A request such as "do the eight interviews support the three hypotheses about voice AI customer support?" has one part for each hypothesis.

Then decide three things, in the same words the [process](/process/intake/) uses.

| Setting | Options |
|---|---|
| Stakes | Exploratory (it decides what to look at next), decision-informing (one input to a decision that can be revisited at moderate cost), or high-stakes (a costly or hard to reverse decision, one that affects rights, safety or finances, or an authoritative publication). |
| Strength of statement needed | Describe. Show a link between things. Predict, without claiming a cause. Estimate the effect of an action. Explain how or why. |
| Kind of finding wanted | Pattern, difference, contradiction, cause, trend, gap, risk or option ranking. More than one can apply, and you can leave it empty. |

The strength of statement matters most. Each technique has a strongest statement it can support, shown at the top of its page. Of the 236 techniques, 177 can describe at most, 23 can show a link between things, 22 can predict without claiming a cause, 9 can estimate the effect of an action and 5 can explain how or why. If you need to say that an action caused an outcome, only the last two groups can support that.

## 2. Rule out techniques that cannot work on your material

Open the technique's page and read the table headed Requirements on the material. Five requirements always apply: content type (for example text or tables), unit of analysis (for example document, claim or topic), level of detail available, number of sources and whether sources can be joined. A technique that fails one of these cannot run on your material. The [dictionary](/reference/fields/) explains each property.

Other requirements apply only in some cases, such as the structure of the material, its amount, its language and known data problems. Each applies only when its stated condition is met. The page also states the minimum material a technique needs, for example two or more cases for a comparative case study. The skill's script does not apply minimum amounts yet, so check this line yourself.

One exception: a technique that fails only on content type or structure can still run when another technique in your plan produces the input it needs. Its page lists what it needs as input.

## 3. Shortlist, with a limit of ten

Start from the [families](/catalogue/). Each family page says what its techniques are for. Read the line under each technique name, then its When to use it section. Choose in this order:

1. Make sure every part of your request has at least one technique.
2. Include at least one technique that reaches the strength of statement you need, if one fits. If none does, say so in your own write-up.
3. Match the kind of finding you want.
4. Where two techniques serve the same part of the request, prefer a pair that reads the material in different ways, because agreement between them counts for more than agreement between near-copies.

The process stops at ten, a default chosen for the design and not a measured value. Before you keep a technique, read its When it does not fit section and its Failure modes and limits.

## 4. Put them in order

The kind of technique, shown on its page, sets the order. Question techniques come first, then preparation, then primary techniques. Verification and challenge techniques come last, and they work on the findings, not on your material. Primary techniques do not depend on each other, so they can run in any order. Preparation techniques that feed each other run in the order their inputs require.

The kind comes from the technique's job and not from its family. In the stored run, the hypothesis tree is in the family Decompose and map, yet it ran first because it examines the question.

## 5. Add the checks

Each technique page has a section, Library checks by stakes, which lists the minimum checks for your stakes level. Higher levels include the checks of the lower ones. The strength of statement can add more, for example a held-out test for prediction. Checks that need a person apply at high stakes only. The [check library](/reference/checks/) describes each check.

## 6. Read the evidence status

Each technique carries an evidence status, copied from the sources and never upgraded. Tested means at least one published study measured the technique's effect or accuracy (33 techniques). Documented means a text, official guidance or a summary describes it, without a test (150). Practice means it is used with no published description found (13). Unconfirmed means no source was opened or a source failed to load (40). Treat an unconfirmed technique as a lead for you to check, and say so if you rely on it.

## An example from the stored run

The [simulator](/simulator/) replays one run. The request was whether eight interviews support three hypotheses, at decision-informing stakes, wanting to show a link between things, looking for a pattern or a contradiction. Of the 236 techniques, 142 could work on the material. Ten were chosen: the hypothesis tree to examine the question, six primary techniques for the interviews and three techniques to test the findings. The process added one preparation technique, preprocessing sensitivity testing, because stance detection needs a cleaned dataset. You can reach the same shortlist by hand by following the steps above, though it takes much longer.

## What you do not get by hand

The skill applies the personal information rule, counts the techniques that reach your strength of statement, runs the checks that need no person (a spot check, repeat runs and a quote check by code) and records each technique's result in a fixed format. By hand, you do these yourself. The tags on each technique are inference unless a page names a source, so use them as a guide and not as a test.
