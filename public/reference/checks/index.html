    Check library

    A check tests one result for a specific weakness, for example by running the technique a second time or by comparing a sample with the source. Each technique lists the checks it needs at each stakes level, and a higher level includes the checks of the level below. Step 6 applies them. The last two columns say whether a person must be involved and whether the check counts as corroboration of a finding.

    human_involvement says whether a check needs a person. needed: the process cannot do it. It applies at the high-stakes level only, where the process asks the user to review a sample and lists the check as not done if the user does not. Below the high-stakes level the plan leaves it out. optional: code or the model can do it, and a person can too. conditional: needed only when the stated condition holds, and then it follows the rule for needed. none: the process does it. Every check the plan lists that needs no person (including spot checks and repeat runs) is done by the process.
