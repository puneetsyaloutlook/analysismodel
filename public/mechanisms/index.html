    Mechanisms

    The design has 43 mechanisms. Each is a rule or a step that code or the model applies without the user asking for it, and each is grouped by the step where it acts. The skill delivers all of them, and the column Delivered by names the skill text that does. The column Used by names the mechanisms that use the output of this one. A mechanism never uses the output of a later step, so the table reads from step 1 to step 8. A repeat of steps 2 to 4 after an edit at 5.1 and a follow-up round are the only returns to an earlier step, and they are described in sections 6 and 7. The examples are illustrations written for this table. They are not results of a run. The rules in sections 3 to 7 are the authority for each mechanism (decisions 72 and 73).

    M03Brief with origin marksEach part of the brief is marked as stated by the user, inferred from the wording or missing.     M04Request parts with scopeThe model splits the request into parts and tags each one. Material means the supplied text can answer it. Topic means answering needs evidence from outside.     IDMechanismWhat it doesExampleDelivered byUsed by
    M12Coverage ruleThe model chooses so that every part of the request has a technique that can answer it, and at least one technique reaches the strength needed. A technique with scope text serves only material parts.A topic part is not counted as answered by a technique that only reads the supplied text.SKILL.md step 3; step3_choose.mdM13, M14, M15
    M13Different-methods pairingWhere two techniques serve the same part, the model prefers a pair that reads the material in different ways, so that their agreement counts for more in step 7.One technique counts cases and another searches for statements that disagree.step3_choose.md; combine.mdM34
    M14Question for unanswerable partsWhen no eligible technique can answer a part, one question offers three choices: add outside evidence, edit the request, or continue without that part. With no reply the run continues without it.The first paragraph of the answer names the part that was left out.SKILL.md step 3; step3_choose.mdM23, M21
    M15Ten-technique limit and reserve listAt most ten techniques are chosen. The others go on a reserve list that only a follow-up round uses.An eleventh technique the model wanted is kept for a follow-up round.SKILL.md step 3; step3_choose.mdM43

    Step 5.2: Prepare the material

    IDMechanismWhat it doesExampleDelivered byUsed by
    M22Additional source lookupFor a technique that needs an additional source, the model looks in the user's material first, then finds one item from any source type, and asks the user only when it finds none. A technique with no item is dropped.A comparator found in the user's own material is used and its location is recorded.SKILL.md step 5 (5.2); technique_record.pyM24, M35
    M23Outside evidence gatheringFor each topic part, when outside evidence is allowed, the model writes one to four questions that evidence could answer and saves each source in the evidence base.How common something is, or what a group of vendors claims.SKILL.md step 5 (5.2); gather_evidence.mdM24, M27
    M24Source purpose ruleA source shows either what it says or does, or what is true. Promotional, advocacy and opinion sources cannot stand alone for what is true, so the finding is unconfirmed unless an independent source agrees.A vendor's claim about its product is reported as a claim, not as a fact about the product.gather_evidence.md; combine.mdM35

    Step 5.3: Analyse the material

    IDMechanismWhat it doesExampleDelivered byUsed by
    M25Method steps for low-evidence techniquesA technique whose evidence status is practice or unconfirmed carries numbered steps from a named source. The agent follows them in order and says where the material cannot supply what a step needs.A step that needs a second source is marked as not possible when the material has one source.technique_record.py; run_technique.mdM27
    M26Result formatEvery technique has a result format that names the parts of its result. The agent writes the result in that format.A result is a table with one row per category and a count for each.technique_record.py; run_technique.mdM27
    M27Independent runsEach primary technique runs in its own agent on the brief and the material, and never reads another technique's result.Two techniques that reach the same finding did so without seeing each other's work.SKILL.md (rules); run_technique.mdM29, M34
    M28Drop on failureA technique whose run does not finish is dropped with the reason. The process never writes a result for it, and the answer lists it.A technique stopped by a usage limit is listed as did not finish.SKILL.md (rule 8)M42

    M30Checks done by codeThe source-span check, the spot check and repeat runs are done by code or by running the technique again.     M31Checks that need a personHuman, independent and expert review apply only at high stakes. The process stops and shows a small sample.     Step 7: Combine the findings

    IDMechanismWhat it doesExampleDelivered byUsed by
    M32Fixed combining methodsThe agreement table runs when two or more techniques ran, and the narrative summary always runs. Pooling runs when the user confirms that estimates measure the same thing. Decision analysis runs when an option ranking is wanted.Pooling is asked about only when two estimates could be on the same scale.SKILL.md step 7; combine.mdM34, M36
    M33Chosen conclusion techniquesThe model chooses at most three conclusion techniques and drops any that needs material the brief does not hold. They change how a conclusion is formed or how its uncertainty is stated, never the label rule.A technique that needs a panel is dropped and the answer says so.SKILL.md step 7; select.py; step78_choose.mdM34
    M34Confidence rule with limitsEach conclusion gets a label (high, medium or low) and a reason. High needs two techniques with different methods that agree and passed checks. A source wording that code could not check, a person check not done, or the same method keeps a label at medium. A failed check at high stakes makes it low.Two techniques agree, but one rests on a fetch summary, so the label is medium.SKILL.md step 7; combine.mdM37, M38, M40
    M35Limit from unchecked sourcesA conclusion that depends on an additional source whose wording code could not check is limited to medium, and the reason names the source.A finding that rests on a page summarised by a fetch tool.combine.md; answer.mdM34
    M36Conflict namingFor each conflict between findings the process names the cause, or states that the conflict is unresolved.Two techniques disagree because they counted different units.combine.mdM43
    M37Facts about the textA finding that anyone can check by reading the text is a fact about the text. It gets the label none and a reason that says it was read directly. A judgement about the text gets a label.A text names no source for a claim.SKILL.md steps 7 and 8; combine.mdM40
    M38InsightsWritten when the request asks for insights or a conclusion goes against what the request assumed. Each states what a reader would expect and what the analysis found instead. Recommendations are given only when the request asks.The expectation is stated first and the finding that differs follows.SKILL.md step 7; combine.mdM40
