    CH-03 Devil's advocacy

    Builds the strongest case against the dominant view or plan, starting from its most vulnerable assumptions, and produces a labelled devil advocate finding.

    ChallengeEvidence: DocumentedChallenge technique, runs in step 6Strongest statement: describe

    What it does

    Builds the strongest case against the dominant view or plan, starting from its most vulnerable assumptions. Artefact: findings presented to the group, labelled as devil's advocate product; read the vulnerable assumptions the advocate could not defend.

    When to use it

    Use when a view or plan is accepted too easily and you want the best case against it before a decision.

    When it does not fit

    The advocate is the plan's author (inference), or challenges are not taken seriously, which gives false confidence.

    Result format

    The result is a set of findings that make the strongest case against the dominant view or plan, starting from its most vulnerable assumptions and labelled as a devil's advocate product. It names the vulnerable assumptions that the advocate could not defend.

    Failure modes and limits

    Model suitabilitymodel alone
    Typical model failureProduces a mild objection that the plan already answers, or argues a position the model itself drafted.
    Error sourcesinput data; coder or rater judgement; language model
    Certainty limitsThe CIA primer notes it takes analytic time; false confidence results when the challenge is not taken seriously, and there is no controlled evidence.

    Related techniques

    Evidence and tag basis

    Documented. The CIA primer notes it takes analytic time; the UK handbook pairs it with overconfidence; no controlled evidence found. (CIA Tradecraft Primer (2009); UK Red Teaming Handbook)

    Tag basis: input profile inference; selection inference; sequencing inference; robustness inference. All tag values are inference unless a source is named.
