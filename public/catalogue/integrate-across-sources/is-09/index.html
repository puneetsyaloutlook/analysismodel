    IS-09 Quantitising and qualitising (data transformation)

    Converts one data type into the other, for example by counting coded themes, and produces a single-type dataset of frequencies or profiles.

    Integrate across sourcesEvidence: UnconfirmedAnalysis technique, runs in step 5.3Strongest statement: describe

    What it does

    Converts one data type into the other, for example by counting coded themes, so that the two can be compared directly. Artefact: a single-type dataset. Read the frequencies or profiles produced.

    When to use it

    Use when you need to compare coded text with numeric data directly, or to turn numeric patterns into profiles that can be read.

    When it does not fit

    Fits when coding is reliable. Misuse: reading theme counts from a non-random sample as prevalence.

    Result format

    The result is a single-type dataset in which the coded themes have been converted into counts, with one row per case or group and one column per theme. It reports the frequencies or profiles produced and states whether the sample supports reading the counts as prevalence.

    Failure modes and limits

    Model suitabilitymodel plus code
    Typical model failureCounts themes in prose without code, and presents counts from a purposive sample as population shares.
    Error sourcesinput data; coder or rater judgement; data transformation
    Certainty limitsCertainty drops with unreliable coding and with samples that do not represent the population (indirectness and risk of bias).

    Related techniques

    • should follow CK-01 Inter-coder agreement statistics (percentage agreement; Cohen's kappa; weighted kappa; Scott's pi; Fleiss' kappa; Krippendorff's alpha; intercoder reliability testing): coding must be shown to be reliable before it is counted
