    PE-04 Data profiling and rule-based validation (data audit; data quality assessment; edit checks)

    Describe the structure, completeness, validity and consistency of each field and test explicit rules, giving a profile table per column and a list of records that break each rule.

    Prepare and extractEvidence: DocumentedPreparation technique, runs in step 5.2Strongest statement: describe

    What it does

    Describes the structure, completeness, validity and consistency of each field and tests explicit rules such as end date after start date. Artefact: a profile table per column and a list of records that break each rule. Read for missing patterns, impossible values, duplicate keys and inconsistent codes.

    When to use it

    Use when you have received a table or dataset and need to know its quality before any analysis.

    When it does not fit

    Always applicable as a first step. Profiling shows that a value is odd, not that it is wrong. The analyst chooses the rule set, and it is never complete.

    Result format

    The result has a profile table with one row per column, giving its type, completeness, valid range and consistency, and a list of the records that break each stated rule. It ends by naming the missing patterns, impossible values, duplicate keys and inconsistent codes found.

    Failure modes and limits

    Model suitabilitymodel plus code
    Typical model failureReports that odd values are errors and writes a short rule set as if it were complete.
    Error sourcesinput data; data transformation
    Certainty limitsCertainty about quality drops when the rule set is short (reporting bias) or when field definitions are undocumented (indirectness).

    Related techniques

    • pairs with HE1-21 Distribution, outlier and base-rate checks: distribution and outlier checks examine the shape of values that profiling flags
    • pairs with MM-02 Algorithmic outlier and anomaly detection (Isolation Forest; Local Outlier Factor; Elliptic Envelope; One-Class SVM (support vector machine)): algorithmic outlier detection finds unusual values that explicit rules miss

    Evidence and tag basis

    Documented. The Australian Bureau of Statistics (ABS) framework defines seven quality dimensions. RADAR names five artefact classes: missing data, bad values, outliers, inconsistent formatting and inconsistent logic. The column profile layout is practice with no authoritative definition. (ABS data quality framework; RADAR, arXiv 2506.08249)

    Tag basis: input profile inference; selection inference; sequencing inference; robustness inference. All tag values are inference unless a source is named.
