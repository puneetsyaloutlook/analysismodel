    PJ-11 Agent-based modelling and Monte Carlo simulation (microsimulation)

    Simulate agents or random draws many times to give an outcome distribution with tail probabilities and the inputs that account for the spread, as a draft result.

    Project forwardEvidence: UnconfirmedPrimary technique, runs in step 5.3Strongest statement: predict, without claiming a cause

    What it does

    Simulates individual agents or random draws many times. Artefact: an outcome distribution; read tail probabilities and which inputs account for the spread.

    When to use it

    Use when the outcome depends on several uncertain inputs or on the behaviour of many actors and you need a distribution, not a single estimate.

    When it does not fit

    Input distributions are invented or the model was never validated against a historical outcome.

    Result format

    The result is an outcome distribution from the repeated simulation runs. It gives the tail probabilities and names the inputs that account for most of the spread.

    Method steps

    1. State the outcome to be estimated and the model that links inputs to it.
    2. For each uncertain input, choose a probability distribution and give its range and the basis for it. For an agent-based model, define the agents, their rules and their starting conditions instead.
    3. Run the model many times, drawing inputs at random each time.
    4. Check that the output has stabilised by comparing results from more runs.
    5. Summarise the output as a distribution: the median, the percentiles and the tail probabilities.
    6. Test which inputs account for most of the spread by varying them one at a time.
    7. Write the result: the output distribution, the tail probabilities, the inputs that matter most, and the assumptions behind each input distribution.

    Steps drawn from: the common description of Monte Carlo simulation (define the model, define input distributions, run many iterations, analyse the output). Pages found for it are from software vendors and are leads only. No source has been opened for the agent-based part.

    Failure modes and limits

    Model suitabilitymodel plus code
    Typical model failureChooses input distributions without a stated basis and reports tail probabilities as if the model had been validated.
    Error sourcesinput data; statistical assumptions; expert opinion
    Certainty limitsCertainty drops when inputs are invented (risk of bias), when the model was not validated against history (indirectness), or when few runs are made (imprecision).

    Related techniques

    • should follow PJ-06 Structured expert elicitation (IDEA protocol: investigate, discuss, estimate, aggregate): elicited ranges give defensible input distributions
    • pairs with TC1-17 Sensitivity analysis (robustness check, leave-one-out): sensitivity analysis identifies which inputs account for the spread
    • should follow CH-01 Key assumptions check (assumptions check): a key assumptions check exposes invented inputs
