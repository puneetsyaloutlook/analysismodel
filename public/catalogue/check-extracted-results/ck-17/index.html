    CK-17 Source-span and quotation check by code (quote-and-verify; extractive grounding; citation verification)

    Require each extracted statement to point to the exact passage it came from, confirm by string match that the passage exists, and produce a pass or fail list per statement.

    Check extracted resultsEvidence: DocumentedVerification technique, runs in step 6Strongest statement: describe

    What it does

    Requires each extracted statement to point to the exact passage it came from, then confirms by string match that the passage exists. A reviewer or entailment check then confirms the passage supports the claim. Artefact: a pass or fail list per statement.

    When to use it

    Use when a model has produced statements with quotations or citations and you need to know whether the quoted passages really exist in the source.

    When it does not fit

    Needs the source as text. Misfit: the quoted span is a paraphrase, or exists but does not support the claim.

    Result format

    The result is a pass or fail list with one row per extracted statement, giving the statement, the exact passage it points to, whether that passage exists by string match and whether the passage supports the claim. It ends with the list of statements that failed.

    Failure modes and limits

    Model suitabilitymodel plus code
    Typical model failureFabricates quotations that look verbatim, or attaches real quotes to claims they do not support.
    Error sourcesinput data; data transformation; language model
    Certainty limitsCertainty drops when passages are paraphrases and not exact matches (indirectness) and when matched passages are not read for support (risk of bias).

    Related techniques

    • should follow PE-10 Schema-based structured extraction with an LLM (LLM (large language model) information extraction; form filling from documents): extracted fields should carry source spans
    • should follow PE-12 Model summarisation of documents (abstractive summarisation; multi-document summarisation): summary statements should be tied to passages
    • should follow PE-13 Retrieval-augmented analysis (RAG (retrieval-augmented generation); grounded question answering over a corpus): cited passages are checked for existence
    • pairs with CK-16 Entailment-based consistency check (textual entailment; NLI (natural language inference) consistency; SummaC; FactCC; faithfulness checking): entailment checks whether the passage supports the claim
    • pairs with TC-04 Claim and citation verification against source text (fact verification; claim checking; citation support check; quotation accuracy check): claim verification judges support against evidence

    Evidence and tag basis

    Documented. One approach extracts both the supporting source span and the inconsistent span, and human evaluation found the span extraction helpful (abstract). NIST requires review and verification of sources and citations in outputs. (Kryscinski et al., arXiv 1910.12840; NIST AI 600-1)

    Tag basis: input profile inference; selection inference; sequencing inference; robustness inference. All tag values are inference unless a source is named.
